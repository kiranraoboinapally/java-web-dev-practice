# 1. First: We Have a Computer

From the previous section, we know a computer has hardware:

```text
             COMPUTER
                |
     +----------+----------+
     |          |          |
    CPU        RAM       Storage
     |
    NIC
```

The hardware physically exists.

For example:

```text
CPU
RAM
SSD
Network Card
Keyboard
Monitor
```

But here's the problem:

## How do we actually use this hardware?

Suppose you want to:

```text
Open Chrome
Create a file
Save a file
Run a command
Connect to another computer
Run a program
```

You don't directly tell the CPU:

> "Take these electrical signals and use this section of RAM."

That would be extremely complicated.

Something needs to manage the hardware for us.

That thing is the:

# Operating System

---

# 2. What Is an Operating System?

An **Operating System**, usually called an **OS**, is the main software that manages a computer's hardware and provides an environment for programs to run.

Examples:

```text
Windows
Linux
macOS
```

Think of the computer like this:

```text
              APPLICATIONS
        +---------+---------+
        |         |         |
      Chrome    VS Code    Browser
        |         |         |
        +---------+---------+
                  |
                  ↓
          OPERATING SYSTEM
                  |
        +---------+---------+
        |         |         |
       CPU       RAM      Storage
        |         |         |
        +---------+---------+
                  |
               HARDWARE
```

The OS sits between your applications and the hardware.

---

# 3. Why Do We Need an OS?

Imagine there is **no operating system**.

You have:

```text
CPU
RAM
SSD
Keyboard
Monitor
```

but your application has to directly control all of them.

For example, if a program wants to save:

```text
hello.txt
```

it would need to understand:

* Where the disk is
* How the disk works
* Where to put the data
* How the filesystem works
* How to communicate with the hardware

That's too much responsibility for every application.

Instead:

```text
Application
     |
     | "Save this file"
     ↓
Operating System
     |
     | handles the hardware
     ↓
Storage
```

So the OS provides a **common way for applications to use hardware**.

---

# 4. Simple Real-Life Example

Think about a restaurant.

```text
Customer
   ↓
Waiter
   ↓

   ↓

```

The customer doesn't go into the kitchen and operate the stove.

Instead, the waiter communicates with the kitchen.


The application doesn't normally directly manage the hardware.

The OS manages it.

# 6. What Is Linux?

Now we come to the important word:

# Linux

Linux is an **operating-system kernel**.

The word **kernel** is important, so let's understand it first.

---

# 7. What Is a Kernel?

The **kernel** is the core part of an operating system.

It is responsible for communicating with and managing hardware and providing fundamental services to programs.

Think:

```text
Applications
     |
     ↓
   Kernel
     |
     ↓
 Hardware
```

For example:

```text
Application
    |
    | "I need memory"
    ↓
Kernel
    |
    ↓
RAM
```

Or:

```text
Application
    |
    | "I need to read this file"
    ↓
Kernel
    |
    ↓
Storage
```

So:

> **Kernel = the core of the operating system that manages access to hardware and provides fundamental system functions.**

---

# 8. Linux vs Operating System — Important!

You will often hear people say:

> "Linux is an operating system."

That's common usage, but technically:

**Linux itself is the kernel.**

A complete Linux-based operating system contains:

```text
Linux Kernel
     +
System tools
     +
Libraries
     +
Applications
     +
Package management
     +
Configuration
```

Together these form a usable Linux operating system.

---

# 9. What Is a Linux Distribution?

A **Linux distribution**, often called a **distro**, is a complete operating system built around the Linux kernel.

Examples:

```text
Red Hat Enterprise Linux (RHEL)

Debian
Rocky Linux

```

Think:

```text
                Linux
                Kernel
                   |
        +----------+----------+
        |          |          |
       RHEL      Ubuntu     Debian
```

They all use the Linux kernel but package and configure the surrounding software differently.

A **program** is software containing instructions that a computer can execute.

For example:


Think:


# 13. Program vs Process

This distinction is extremely important in Linux.

### Program

A program is the software itself.

For example:

```text
firefox
```

### Process

When that program is actually running, it becomes a **process**.

```text
Program
   ↓
Started
   ↓
Process
```

Example:

```text
firefox
   ↓
Running Firefox
   ↓
Process
```

So:

> **Program = software stored on the system.**

> **Process = a running instance of a program.**

---

# 14. Why Do We Need Processes?

Suppose you open:

```text
Terminal
Browser
Text editor
```

The computer has to manage all of them simultaneously.

Conceptually:

```text
Linux
 |
 +--- Terminal process
 |
 +--- Browser process
 |
 +--- Editor process
 |
 +--- Other processes
```

The kernel manages these processes and decides how CPU and other resources are used.

---

# 15. What Is RAM Doing Here?

Remember from the previous section:

> RAM is temporary working memory. 

When a program runs, it needs memory.

So:

```text
Program stored on disk
        ↓
Program starts
        ↓
Loaded into RAM
        ↓
Becomes a process
        ↓
CPU executes it
```

This is the connection between your **computer fundamentals** and **Linux**.

---

# 16. What Is a User?

A Linux system can have multiple users.

For example:

```text
student
admin
root
```

A **user** is an identity that can interact with the system.

The operating system uses users to determine:

> Who is doing something?

For example:

```text
student runs command
```

Linux knows:

```text
User = student
```

This becomes very important for security.

---

# 17. What Is `root`?

`root` is the **superuser account** in Linux.

It has very high privileges.

Think:

```text
Normal user
     ↓
Limited permissions

root
     ↓
Very high system privileges
```

For example, a normal user may not be allowed to modify certain system files.

`root` generally can.

---

# 18. Why Don't We Always Use root?

Because if you make a mistake as root, you can potentially damage the entire system.

For example:

```text
Normal user
   ↓
Limited damage

root
   ↓
Can modify critical system resources
```

So Linux systems normally encourage using a normal account for everyday work and elevated privileges only when needed.

---

# 19. What Is the Filesystem?

Now we come to another major Linux concept.

Your computer has storage.

Storage contains data.

Linux organizes that data into a **filesystem**.

A filesystem is a structure used to organize and store files and directories.

Think of it like a filing cabinet:

```text
Filing Cabinet
     |
     +--- Folder
     |      |
     |      +--- File
     |
     +--- Folder
            |
            +--- File
```

Linux has a similar concept.

---

# 20. What Is a File?

A file is a unit of stored information.

Examples:

```text
notes.txt
photo.jpg
config.conf
script.sh
```

A file can contain:

* Text
* Configuration
* Code
* Binary data
* Program data

# 21. What Is a Directory?

A **directory** is what we commonly call a folder.

For example:

```text
Documents/
Pictures/
Downloads/
```

Directories organize files.

Example:

```text
/home/student
       |
       +--- notes.txt
       +--- project/
       |       |
       |       +--- app.py
       |
       +--- downloads/
```

---

# 22. Linux Filesystem Starts at `/`

This is very important.

Linux doesn't organize its filesystem using:

```text
C:\
D:\
```

in the same way Windows commonly does.

Linux has a starting point called:

```text
/
```

This is called the **root directory**.

Do not confuse:

```text
/
```

with:

```text
root
```

They are different things.

```text
/       → root directory
root    → root user
```

---

# 23. Basic Linux Filesystem

You will commonly see:

```text
/
├── /etc
├── /home
├── /root
├── /tmp
├── /usr
├── /var
└── /boot
```

We don't need to memorize everything yet.

Just understand that different directories have different purposes.

```text

   |

   +--- user2
```

# 25. `/root`

This is the home directory of the `root` user.

Again:

```text
/root
```

is a directory.

Whereas:

```text
root
```

is the superuser account.

# 26. `/etc`

`/etc` contains many system configuration files.

For example:

```text
/etc/...
```

Think:

> `/etc` = an important place for system configuration.

# 27. `/var`

`/var` contains data that commonly changes while the system is running.

For example:

```text

application data
spool data
```

You will frequently encounter:

```text
/var/log
```

which contains system/application logs.

# 28. `/tmp`

# 29. What Is the Terminal?

The **terminal** is an interface through which you can interact with the computer using commands.

Instead of clicking:

```text
Folder → File → Open
```

you can type commands.

For example:

```bash
ls
```

---

# 30. What Is a Shell?

The terminal itself isn't exactly the shell.

A **shell** is a program that interprets commands you type.

Think:

```text
You
 ↓
Terminal
 ↓
Shell
 ↓
Linux
 ↓
Hardware
```

For example:

```bash
ls
```

You type:

```text
ls
```

The shell interprets that command and runs the appropriate program.

---

# 31. What Is Bash?

**Bash** is one popular Linux shell.

Bash means:

> **Bourne Again SHell**

You'll commonly see:

```text
[user@server ~]$
```

That is a shell prompt.

You type:

```bash
ls
```

and Bash interprets it.

---

# 32. What Is a Command?

A command is an instruction you give through the shell.

Examples:

```bash
ls
pwd
cd
mkdir
cp
mv
rm
```

For example:

```bash
pwd
```

asks:

> "Where am I currently located?"

---

# 33. What Is a Service?

A **service** is a program designed to provide some functionality, often continuously in the background.

For example:

```text
Linux
 |
 +--- SSH service
 +--- Web server service
 +--- Database service
```

A service may start automatically when the system boots.

Later you'll learn:

```bash
systemctl status sshd
```

But don't worry about `systemctl` yet.

---

# 34. What Is a Package?

A **package** is a collection of software files prepared so that software can be installed, updated, and removed using a package-management system.

For example:

```text
Application
   ↓
Package
   ↓
Installed into Linux
```

On RHEL, you'll commonly encounter:

```text
rpm
dnf
```

Again, we'll learn these properly later.
