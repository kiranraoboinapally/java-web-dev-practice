
# 00.02.1 — Linux Hands-On Basics

## 1. First: Where am I?

When you open a Linux terminal, you are always considered to be **inside some directory**.

For example:

```text
/
└── home
    └── student
        └── projects
```

You might currently be here:

```text
/home/student/projects
```

Linux needs a way to tell you where you currently are.

That's what `pwd` does.

---

# 2. `pwd` — Where am I?

Run:

```bash
pwd
```

`pwd` means:

> **Print Working Directory**

Example:

```text
/home/student
```

It tells you your current location in the filesystem.

Think of it like:

> "What folder am I currently standing in?"

---

# 3. `ls` — What is here?

Now run:

```bash
ls
```

It lists the contents of your current directory.

Example:

```text
Documents
Downloads
Pictures
projects
```

Think:

```text
pwd
 ↓
Where am I?

ls
 ↓
What is inside here?
```

---

# 4. `ls -l` — Show more information

Run:

```bash
ls -l
```

You may see something like:

```text
drwxr-xr-x  2 student student 4096 Documents
-rw-r--r--  1 student student  120 notes.txt
```

Don't worry about every column yet.

For now, understand:

> `ls -l` gives a **long/detailed listing** instead of just names.

We'll properly learn those permissions later.

---

# 5. `ls -a` — Show hidden files

Run:

```bash
ls -a
```

You may see:

```text
.
..
.bashrc
.profile
Documents
```

Files beginning with `.` are generally treated as **hidden files** in normal directory listings.

So:

```bash
ls
```

shows normal entries.

```bash
ls -a
```

shows normal + hidden entries.

---

# 6. `cd` — Move somewhere else

Now suppose you have:

```text
/home/student
    |
    +--- Documents
    +--- Downloads
    +--- projects
```

You can move into `Documents`:

```bash
cd Documents
```

Then:

```bash
pwd
```

might show:

```text
/home/student/Documents
```

So:

> `cd` = **change directory**

---

# 7. Going Back

Suppose you're here:

```text
/home/student/Documents
```

Run:

```bash
cd ..
```

You go one level up:

```text
/home/student
```

`..` means:

> **parent directory**

So:

```text
/home/student/Documents
                    ↑
                  parent
```

---

# 8. `.` — Current Directory

There is another special notation:

```text
.
```

It means:

> **current directory**

So Linux has two useful concepts:

```text
.   → current directory
..  → parent directory
```

This becomes extremely useful later.

---

# 9. `cd ~` — Home Directory

Run:

```bash
cd ~
```

This takes you to your user's home directory.

For example:

```text
/home/student
```

`~` represents the current user's home directory.

So:

```bash
cd ~
```

means approximately:

> "Go to my home directory."

---

# 10. `cd /` — Root Directory

Now:

```bash
cd /
```

Then:

```bash
pwd
```

You get:

```text
/
```

Remember from the previous section:

```text
/
```

is the **root directory of the Linux filesystem**.

It is the top of the filesystem hierarchy.

---

# 11. Important Difference: `/` vs `root`

Don't confuse these:

```text
/
```

and:

```text
root
```

They mean different things.

### `/`

Root directory:

```text
/
├── etc
├── home
├── var
└── usr
```

### `root`

The superuser account.

And:

```text
/root
```

is the home directory of the `root` user.

---

# 12. Creating a Directory — `mkdir`

Suppose you're in:

```text
/home/student
```

and want to create a project directory.

Run:

```bash
mkdir project
```

Now:

```bash
ls
```

will show:

```text
project
```

`mkdir` means:

> **make directory**

So:

```bash
mkdir project
```

means:

> Create a directory called `project`.

---

# 13. Creating a File — `touch`

Now go inside:

```bash
cd project
```

Create a file:

```bash
touch notes.txt
```

Then:

```bash
ls
```

You should see:

```text
notes.txt
```

`touch` can create an empty file if the file doesn't already exist.

So:

```text
mkdir → directory
touch → file
```

---

# 14. Looking at File Contents — `cat`

Suppose you have:

```text
notes.txt
```

You can put some content into it:

```bash
echo "Hello Linux" > notes.txt
```

Then:

```bash
cat notes.txt
```

Output:

```text
Hello Linux
```

`cat` can display the contents of a file.

Think:

```text
cat file
   ↓
show file contents
```

---

# 15. What did `>` do?

This is important.

When you ran:

```bash
echo "Hello Linux" > notes.txt
```

the:

```text
>
```

is **output redirection**.

It means:

> Take the command's output and put it into this file.

Conceptually:

```text
echo
  |
  | "Hello Linux"
  ↓
notes.txt
```

If the file already has content, `>` normally replaces the existing contents.

---

# 16. `>>` — Append

Now run:

```bash
echo "Second line" >> notes.txt
```

Then:

```bash
cat notes.txt
```

You get:

```text
Hello Linux
Second line
```

The difference:

```text
>   → replace/write
>>  → append
```

This distinction becomes very important when working with Linux logs and configuration.

---

# 17. `cp` — Copy

Suppose you have:

```text
notes.txt
```

You want a copy:

```bash
cp notes.txt notes-backup.txt
```

Now:

```bash
ls
```

might show:

```text
notes.txt
notes-backup.txt
```

`cp` means:

> **copy**

Conceptually:

```text
notes.txt
    |
    +-------> notes-backup.txt
```

---

# 18. `mv` — Move

Suppose you create:

```bash
mkdir backup
```

Then:

```bash
mv notes-backup.txt backup/
```

Now the file is inside:

```text
backup/
└── notes-backup.txt
```

`mv` means:

> **move**

It can also be used to rename files.

For example:

```bash
mv notes.txt linux-notes.txt
```

Now:

```text
notes.txt
```

becomes:

```text
linux-notes.txt
```

So `mv` can mean:

```text
move
OR
rename
```

depending on how you use it.

---

# 19. `rm` — Remove

If you want to delete:

```text
linux-notes.txt
```

you can use:

```bash
rm linux-notes.txt
```

Then:

```bash
ls
```

It is gone.

`rm` means:

> **remove**

⚠️ Be careful with `rm`.

Unlike a graphical desktop's recycle bin, command-line deletion may not give you an easy recovery option.

---

# 20. Removing a Directory

For an empty directory:

```bash
rmdir directory_name
```

For example:

```bash
mkdir test
rmdir test
```

But if the directory contains files, `rmdir` won't remove it.

You will later encounter:

```bash
rm -r directory_name
```

`-r` means recursive.

That means:

> Remove the directory and things inside it.

**Be very careful with `rm -r`.**

---

# 21. `less` — Read Large Files

`cat` is convenient for small files.

But imagine a file has:

```text
10,000 lines
```

Running:

```bash
cat huge-file.txt
```

could flood your terminal.

Instead:

```bash
less huge-file.txt
```

allows you to view the file page by page.

This is especially useful for:

```text
logs
configuration
large text files
```

---

# 22. `head` — Beginning of a File

```bash
head notes.txt
```

shows the beginning of the file.

You can also specify how many lines:

```bash
head -n 5 notes.txt
```

Meaning:

> Show the first 5 lines.

---

# 23. `tail` — End of a File

Similarly:

```bash
tail notes.txt
```

shows the end of the file.

This becomes extremely useful with logs.

For example:

```bash
tail /var/log/...
```

And later you'll see:

```bash
tail -f logfile
```

which allows you to watch new lines being added to a log.

---

# 24. `clear`

Your terminal can become messy.

Run:

```bash
clear
```

It clears the visible terminal screen.

It doesn't delete your files.

It simply cleans up the terminal display.

---

# 25. `whoami` — Who Am I?

Run:

```bash
whoami
```

Example:

```text
student
```

It tells you which user account you're currently using.

This is useful because Linux permissions depend heavily on **who you are**.

---

# 26. `id` — More Information About Your User

Run:

```bash
id
```

You may get something like:

```text
uid=1000(student) gid=1000(student) groups=1000(student)
```

Don't memorize the numbers yet.

Just understand:

> `id` gives information about your Linux user identity and groups.

We'll properly explain:

```text
UID
GID
groups
permissions
```

in the next Linux section.

---

# 27. `man` — Manual Pages

Linux has built-in documentation.

For example:

```bash
man ls
```

This opens the manual page for `ls`.

You can also do:

```bash
man cp
man mv
man mkdir
```

This is one of the most important habits to develop in Linux:

> **Learn how to read the system's own documentation.**

---

# 28. Commands Have a General Structure

You'll frequently see commands like:

```bash
command option argument
```

For example:

```bash
ls -l /etc
```

Break it down:

```text
ls       → command
-l       → option
/etc     → argument
```

Another:

```bash
mkdir project
```

```text
mkdir    → command
project  → argument
```

---

# 29. What Is an Option?

An option modifies how a command behaves.

For example:

```bash
ls
```

versus:

```bash
ls -l
```

The command is still:

```text
ls
```

but:

```text
-l
```

changes the behavior.

You can often see options with:

```bash
man command
```

or:

```bash
command --help
```

For example:

```bash
ls --help
```

# 30. Your First Linux Filesystem Exercise

Now you can connect all of this.

Start:

```bash
cd ~
```

Check:

```bash
pwd
```

Create a directory:

```bash
mkdir linux-lab
```

Enter it:

```bash
cd linux-lab
```

Create a file:

```bash
touch notes.txt
```

Check:

```bash
ls -l
```

Put text into it:

```bash
echo "Linux fundamentals" > notes.txt
```

Read it:

```bash
cat notes.txt
```

Create a backup:

```bash
cp notes.txt notes-backup.txt
```

Check:

```bash
ls -l
```

Create another directory:

```bash
mkdir backup
```

Move the backup:

```bash
mv notes-backup.txt backup/
```

Check:

```bash
ls
```

Then:

```bash
ls backup
```

You should understand the resulting structure:

```text
linux-lab/
│
├── notes.txt
│
└── backup/
    └── notes-backup.txt
```

# 32. Don't Memorize Commands Yet

The important thing isn't:

> "Can I remember 20 Linux commands?"

The important thing is understanding the relationship:

```text
Linux filesystem
       ↓
Directories
       ↓
Files
       ↓
Commands
       ↓
Shell
       ↓
Linux
```

For example:

```bash
cd /etc
```

means:

```text
You
 ↓
Bash
 ↓
cd command
 ↓
Linux changes your current directory
 ↓
You are now inside /etc
```
